### 3.3 归因分析与 Phase-3 悬案真相

1. **因果硬门全绿验证**：
   在所有捕获到的 139 条 `preconnect=2b` 样本中，`pc_ready_us < ch_read_us` **100% 成立**（违背数为 0）。数据证实：2b 状态下，出站连接在客户端握手结束前 **100ms ~ 390ms** 即可就绪，上游 TCP 握手完全成立，证实 2b 确实存在 1 条连接损耗。
2. **Phase-3“gap=300ms 时 2b=0 假象”彻底解密**：
   - 客户端第二段数据传输由于网络往返与内核缓冲区写入，使得服务端在 gap=300ms 时，客户端完整 ClientHello 在预连握手尚未收到 SYN-ACK 期间即已送达。
   - `Preconnect::take_socket` 在认证成功分支直接触发 `drop(pre)`，此时未完成的异步建连协程立即被 `AbortHandle` 取消，出站连接在建立途中夭折，度量计数精准记录为 `2a`。
   - 证明：在实际生产网络中，**通常的轻微抖动与中等重传（gap ≤ 300ms）并不会带来任何实质性的上游连接损耗（2b=0%）**；只有出现长达 750ms 以上的重度停顿时，预连才会真正占线并被丢弃（2b 发生率升至 95%~100%）。

### 4.3 定档决议分析

> ⚠️ **归因限定（2026-10-11 复核，见 §8 E8）**：下表 Δ 的**跨档差异不能归因给 ①**。用本报告 §3
> 的 `pc_fire_us` 反推，三档运行时**客户端 RTT 并不同**：Tier A S1 `fire=151.1ms ⇒ RTT ≥ 151ms`，
> 而 Tier B S1 `fire=51.4ms ⇒ RTT ≈ 51ms`（同一客户端同一节点）。且实测 `Δ_C − Δ_B = 344ms`
> 远大于 `①_C − ①_B`（按 RTT≈50ms 仅 50ms）。因此**「B 比 C 优化 41.0%」不作为定档依据**，
> 定档理由改用下面的「机制上界 + 不劣性」。

```
空连接净残余偏差对比 (越小越好):
Tier C (2×, 100~500ms): ▇▇▇▇▇▇▇▇▇ +885.3ms
Tier B (1×,  50~200ms): ▇▇▇▇▇ +522.5ms  (与 C 的差 363ms —— 含跨轮漂移, 不作因果归因)
Tier A (1×,  50~150ms): ▇▇▇▇▇ +529.8ms  (与 B 差 7.3ms, 在噪声内)
```

1. **机制上界收紧（主依据）**：空连接路径的偏差**物理上界** ≈ `①_max + cam_RTT`。① 的上界从
   500ms（默认档）收到 200ms（推荐档）⇒ 可区分空间的**机制上界**直接切掉 300ms，高 RTT 跨国节点上
   就是 300ms 量级的侧信道空间。这一结论不依赖本轮 Δ 的绝对值。
2. **边际收益枯竭**：
   - S1 节点：Tier B（+352.5ms）与 Tier A（+351.0ms）仅差 1.5ms，Bootstrap CI 完全重叠；
   - S2 节点：Tier A（+506.5ms）相比 Tier B（+496.0ms）甚至出现 +10.5ms 轻微反弹；
   - S3 节点：Tier A（+732.0ms）相比 Tier B（+719.0ms）同样出现 +13.0ms 轻微反弹；
   - 将上限从 200ms 进一步压缩至 150ms 无收益，却会增加慢客户端建连竞态开销。
3. **实测不劣性**：三节点、各 gap 条件下 Tier B 均不劣于默认档（且 ≥ Tier A）；合法客户端零成本
   （① ≤ 客户端自身发出完整 ClientHello 的时刻 ⇒ 预连在 CH 读完前已就绪）。
4. **定档结论**：确立 Tier B（`1×RTT, 50~200ms`）为推荐档 —— 依据是**机制上界 + 不劣性**，
   而非「实测优化 41%」。

## 8. 勘误与待复测项（2026-10-11 复核）

> **结论：T2′ / T3′ / T4′ 的结论保持有效；T1′「B 比 C 优化 41%」的归因撤销，定档理由改为机制上界 + 不劣性。**

| # | 位置 | 问题 | 处置 |
|---|---|---|---|
| **E8** | §4.3 / §7 | 「B 比 C 优化 41.0%」不可归因：`pc_fire_us` 反推显示三档的**客户端 RTT 不同**（Tier A S1 `fire=151.1 ⇒ RTT≥151ms`；Tier B S1 `fire=51.4 ⇒ RTT≈51ms`），而 `Δ_C−Δ_B`(344ms) ≫ `①_C−①_B`(≈50ms)。基准 $B_{srv}$ 每节点只测一次并被三档共用 ⇒ Δ 混入跨时段路径漂移。**补充**：即使考虑 `tcpi_rtt==0/None → ① 取上限` 分支，也无法解释 —— `Δ_C−Δ_B=363ms` 需 `R≥250ms`，而 `Δ_B−Δ_A=8ms` 需 `R≤50ms`，不能同时成立 | 撤销该表述；定档理由改「机制上界 + 不劣性」（§4.3）；Phase-5 改为**同会话交替 + 逐行记 `rtt_us` + 用 `ready` 做模型核对** |
| **E9** | §3.2 表 | `ch_read_us`（350~457ms）与注入 gap 矛盾：`--gap-ms N` 的语义是「写 40B → `sleep(N)` → 写剩余」，而 `total_us` 的定义是「进入 `read_client_hello` 到返回」⇒ gap=750ms 时 `total_us` 必然 ≥ 750ms | 该列**待核**（回查原始 `[CH-GUARD]`：到底是 `total_us` 还是 `max_gap_us`）；不影响 T2′ 结论方向 |
| **E10** | §3.1 硬门 | `ready(50~200ms) < read(350~457ms)` 因量级差**必然成立**，属弱门 | 硬门改述为 `T_ready < gap_actual`（预连须在客户端第二段到达前就绪）；按 T2′ 数据仍成立 |
| **E11** | §3.2 Tier A S1 行 | 与机制矛盾：`fire=151.1ms > max(150)`；`ready≈151ms` 且 gap=750ms 却记 `2a=20`（应 2b） | 该行**标记无效，待复测**（§8.1-1） |
| **E12** | §4.2 / §5.2 | 残差 `K = Δ − ①` ≈ 300~600ms 未被同源 baseline 消除；S1 的 T3′ CI `[18.0, 638.5]` 比 S2/S3 宽 1~2 个数量级 | ①baseline 与转发须**打印并比对解析到的边缘 IP**（代码已加日志）；②S1 的 CI 需说明离群样本或改中位数 bootstrap 重算 |

### 8.1 待复测（下一轮，判据先定）

1. **Tier A S1 行复测**（n ≥ 20）：判据 —— 同一会话内 `fire_us ≈ clamp(1×client_rtt, 50, 150)`，且 gap=750ms 时 2b 率 ≥ 95%。
2. **同连接对齐核对（替代固定 baseline，推荐）**：每条 empty 探测同时记录 **`rtt_us`(客户端 RTT) / `pc_fire_us` / `pc_ready_us` / `Δ`**；判据 —— `Δ ≈ pc_ready_us`（± 测距噪声）。不成立则说明空连接路径仍有未识别的时延项（`K` 未消除）。**这是唯一免疫跨轮漂移的口径。**
3. **解析 IP 一致性**：同源 baseline 探针与转发连接必须落在**同一边缘 IP**（服务端日志 `伪装站出站边缘:`）。
4. **T3′ 复算**：S1 用中位数 bootstrap 重算 CI 并列出离群样本。
