## 2. P0 前置（本轮新增，不满足则 T1′/T2′ 的结论无效）

### P0.6 时序归因字段（为 T2′ 定案）
- `[CH-GUARD]` 增两个字段：`pc_fire_us=`（arm → sleep 结束）、`pc_ready_us=`（arm → socket 就绪）。
  实现位置：`handshake.rs` 的 `Preconnect::arm`（set `pc_fire_us` 于 `sleep(delay).await` 之后、`rate_ok()` 之前；
  `pc_ready_us` 于 `connect_camouflage` 返回 Some 之后），存两个 `Arc<AtomicU64>`，与 `has_connected` 同处。
- 探针侧：每条样本输出 `gap_ms` / `split_at`（已有），便于与服务端日志按时间对齐。
- **验收**：能对每一条探测回答"预连建立时刻 vs CH 到齐时刻"，从而**解释**（而非仅计数）2a/2b。

### P0.7 baseline 同源化工具（为 T1′ 定案）
- 目标：让 baseline 与 Mirage 转发路径**同机同 POP 同轮**。
- 做法（二选一）：
  - **(推荐) 服务端侧 baseline**：在 `$S1/$S2/$S3` 上用一条脚本从**服务端主机**连 `$CAM_REAL:443`、**不发任何数据**、测到 FIN 的耗时；
  - 或给探针加 `--baseline-local-cam`：由探针在**服务端**通过 SSH/agent 执行上面的动作（若不想加代码，用 `socat`/`python` + `ts` 手工打点填表即可）。
- **在报告里必须写明**：baseline 与 Mirage 路径是否同源（否则 T1′ 结论无效）。

### P0.8 口径统一（避免与 Phase-3 报告/计划冲突）
- 档位改名（Phase-3 报告与 `plan-phase3` 的 A/B/C 含义不同）：**`默认档`(2×,100~500) · `推荐档`(1×,50~200) · `极限档`(1×,50~150)**。
- `cam_rtt` 一律取**当轮实测**（不回填历史值）。Phase-3 报告 §1 拓扑里的 `S1≈60ms / S2≈75ms` 与其 §3.4 的 `F`（S1 5.2ms / S2 44.6~73.4ms）矛盾（按 `F = 2×cam_rtt + P`，S1/S2 反推应为 ≈2.5ms / 22~36ms）——已在报告加勘误，本轮以实测为准。

## 3. T1′ — ① 定档（同源 baseline + n≥20 + 中位数 CI）

**目的**：在**消除 idle 混淆**之后，判断"推荐档"是否真的优于"默认档"。

```bash
# 每个档位（默认/推荐/极限）分别：
#  1) 服务端同源 baseline（P0.7）：连续 20 次空连接 → 取中位数 = B_srv
#  2) 三节点同轮 empty 探测（n=20，与 baseline 交替发起）
for i in $(seq 1 20); do
  probe_close_timing -t $CAM_REAL:443 -t $S1:9444 -t $S2:9444 -t $S3:9444 \
    --modes empty --count 1 --cap 90 --sni $CAM_REAL
done
```

**统计**：`Δ_i = close(Mirage_i) − B_srv`；报**中位数 Δp50 与 bootstrap 95% CI**（**不用均值**，避免长尾）。

**判据（预注册，三条全满足才改默认）**：
1. `Δp50 ≥ 0`（**不得为负** —— 负值说明 idle 仍不同源，先回 P0.7 排查，不得下结论）；
2. 推荐档的 `Δp50` **小于**默认档，且**两档 CI 不重叠**（否则判为"无差异"，**不得**仅凭"理论上限更小"就改默认）；
3. T2′ 的 `2b` 率在 gap≥550ms 下未显著上升（>5% 即视为显著）。

**回滚判据**：若推荐档 `Δp50` 更差或 CI 与默认档重叠 → **默认保持 `2×,100~500`**，把"① 上限 200ms"降级为**高 RTT 节点可选建议**（机制上界仍成立：`Δ ≤ ①_max + cam_rtt`）。

## 4. T2′ — `2b` 归因重测（每条可解释）

**目的**：查清"到底什么时候会真的建立预连连接"，并撤回/修正 Phase-3 的"零损耗"表述。

- 组合：3 档 × `gap ∈ {100, 200, 300, 550, 750}` × 3 节点；**n ≥ 20/格**。
- 每格记录：`gap`、`ch_complete_us`、`pc_fire_us`、`pc_ready_us`、`preconnect` 值、`authed`。

**判据（预注册）**：
1. **归因自洽**（硬门）：每条 `2b` 必须满足 `pc_ready_us < ch_complete_us`；每条 `2a` 必须满足 `pc_fire_us ≥ ch_complete_us`（或任务在 sleep 中被 abort）。
   **任一样本不满足 ⇒ 停止本轮**，先排查度量/实现（不得用不自洽的数据下结论）。
2. **2b 率**用 Wilson 95% 上界报（不要只写 `0/n`）：`0/5 ⇒ ≤45%`，`0/20 ⇒ ≤16%`，`0/60 ⇒ ≤6%`。
3. 在 gap≥550ms（**真实 RTO 退避区间**）给出 2b 率与"每秒上游连接数"估算，并与旧预热池的 `~0.38 conn/s` 对比。
4. **表述修正**：除非判定 1 通过且 gap≥550ms 下 2b=0，否则不得再写"完全不会产生额外连接消耗"；
   正确表述为"在 gap ≤300ms 未观测到 2b；在 gap ≥550ms 会出现 2b（1 条上游连接/次，频率见实测）"。

## 5. T3′ — 自校准复核（逐条口径 + 中位数 CI）

**目的**：解释 Phase-3 的 Δmean（+187/+169/+249ms），并给自校准一个**不依赖巨宽 CI** 的验收。

1. **预热与收敛判据**（写进报告）：连续 **5 条** `fail_us` 相对变动 <5% 才算收敛；未收敛不得开始成对采样。
2. **逐条导出**：`inj_us` 与 `fail_us` **每一条**都记（不是抽一条核对），并统计：
   - auto 生效样本占比（判据：`inj_us == fail_us`）；
   - **静态度量兜底**样本占比（`inj_us == 2×rtt_us + 100000`）。
3. **统计**：只用 auto 生效样本，报 Δ 的**中位数** + bootstrap CI，并同时报 Δmean/σ 以解释 Phase-3 的正偏差来源（静态兜底占比 vs 长尾）。
4. **判据**：
   - auto 占比 **≥95%**（否则预热不足，延长预热后重跑）；
   - 仅 auto 样本的 `|Δ中位数| ≤ 100ms` 且 CI 覆盖 0。
5. **备注**：Phase-3 的 `CI ∋ 0` 判据**保留但降级**为"未检出偏差"的辅证，不再单独作为"验收通过"的理由。
